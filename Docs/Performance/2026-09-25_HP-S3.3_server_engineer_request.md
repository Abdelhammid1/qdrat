# HP-S3.3 — طلب اختبار الحمل من مهندس السيرفر

إلى: م. عبدالحميد
الموضوع: اختبار الحمل على الصفحة الرئيسية بعد نشر كاش الواجهة العامة (آخر commit: `3b00fa3`)

السلام عليكم يا باشمهندس عبدالحميد،

تم رفع التعديلات على `main`. الصفحة الرئيسية `/` وكل صفحات `_FrontendLayout` (Login وRegister والصفحات العامة) صارت تُقدَّم من `IMemoryCache` بدل استعلامات قاعدة البيانات.

**قياس محلي (زائر مجهول):**

| الصفحة | قبل | بعد |
|---|---|---|
| الرئيسية | 19 استعلام لكل طلب | 0 بعد أول طلب (13 في الطلب البارد) |
| Login | 3 | 0 |

المطلوب منك اختبار هذا الأثر على السيرفر الفعلي.

## 1) النشر
- انشر آخر `main` بالطريقة المعتادة.
- لا توجد Migrations، ولا باكدجات جديدة، ولا مفاتيح إعدادات جديدة.
- الكاش داخل الذاكرة (`IMemoryCache`) ويعمل على instance واحد فقط. لو شغّلت أكثر من instance أخبرني قبل الاختبار، لأن الإبطال لن ينتقل بينها.

## 2) فحص سريع بعد النشر
- افتح `/` و`/Identity/Account/Login` وتأكد أن الـ navbar والأقسام تظهر كما كانت.
- أول طلب بعد التشغيل أبطأ قليلًا (تعبئة الكاش)، وهذا متوقع.

## 3) اختبار الحمل (من جهاز خارج السيرفر)
```
hey -z 30s -c 50 https://qdrat.manasety.ai/
```
شغّله مرتين، وقبل كل مرة اعمل تسخين بطلب واحد:
- **أ) مع** `DOTNET_ThreadPool_ForceMinWorkerThreads=200` (الوضع الحالي).
- **ب) بدون** الـ workaround مؤقتًا. أعد ضبطه بعد الاختبار.

## 4) المطلوب تسجيله لكل تشغيلة
- متوسط زمن الاستجابة.
- p95.
- نسبة الفشل (Non-2xx / timeouts).
- طلبات في الثانية.
- نسبة CPU على السيرفر أثناء الاختبار.
- لو أمكن، ضغط DTU أو اتصالات SQL أثناء الاختبار.

أرسل لي أرقام «قبل» إن كانت عندك من اختبار سابق للمقارنة.

## 5) كيف نقرأ النتيجة
- لو نجح الاختبار (ب) بلا فشل، فالمشكلة كانت من الصفحة الرئيسية وقد حُلّت.
- لو ظل الفشل في (ب) رغم أن الصفحة صارت بلا DB، فالمصدر ليس هذه الصفحة. هو تذكرة #2 (sync داخل Controllers/Services)، وتُعالج على حدة.

## 6) عند أي مشكلة
- لا تعمل rollback مباشرة. أرسل لي رسالة الخطأ من `Logs/log-*.txt` وأخبرني بالنتيجة.

شكرًا يا باشمهندس عبدالحميد.
