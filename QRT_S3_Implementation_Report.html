قواعد العمل

  • الملكية (D6): المدرب يُحدَّد من الجلسة في الخادم، وشرط InstructorId والحالة داخل الاستعلام نفسه — لا IDOR.
  • الاعتماد: نفس تحقق ApproveSingleQuestion: مكتمل، غير مرفوض، إجابة صحيحة مرتبطة بخيار فعلي، وغير معتمد مسبقًا. غير الصالح يُتخطّى وتُذكر الأسباب في الرسالة؛ وإن لم يصلح أي سؤال تفشل العملية بلا تغيير.
  • الأثر على السؤال: IsReviewed وReviewedByUserId وReviewedAt، والعنصر Approved مع IsLockActive=false (D1).
  • الإرجاع (D5): العنصر Returned + ReturnNote؛ السؤال لا يُعتمد ولا يُرفض (القرار للأدمن).
  • الاكتمال: عند PendingItems == 0 تصبح المهمة Completed ويصل CreatedByUserId إشعار. الإشعار خارج الـ Transaction وفشله لا يُفشل العملية.
  • التزامن: Transaction داخل ExecutionStrategy، والتقاط DbUpdateConcurrencyException برسالة «أعد التحميل».
  • الأداء: بلا Query أو SaveChanges داخل حلقة؛ العناصر (≤500) بسؤالها وخياراتها باستعلام واحد وتصفية المعرّفات في الذاكرة (بلا Contains على قائمة داخل SQL). العدادات بـ GROUP BY واحد.
  • النسب (مكان واحد): QuestionReviewTaskMetrics — الاعتماد = المعتمد/الفعلي، الإنجاز = (الفعلي − المعلّق)/الفعلي، والتوقيت يُعرض بـ Arab Standard Time (D9).

الاختبارات

  • اعتماد صالح: السؤال والعنصر والـ Audit والعدادات والانتقال إلى InProgress.
  • اعتماد آخر معلّق: Completed وإشعار الأدمن بـ 100%.

قرارات وملاحظات تحتاج مراجعة
  • الحجز بعد الإرجاع: Returned يفقد الحجز وفق تصميم S1، فيظهر السؤال في المسار العام حتى معالجة الأدمن (S6). تُراجَع قبل S4.2.
  • «تعديل واعتماد» غير معروض عمدًا (S4.1)، وMarkEditedAndApprovedAsync ما زالت Fail.
  • اعتماد الأدمن المباشر لا ينعكس على العنصر قبل S4.3 (يُتخطّى بـ «معتمد مسبقًا»).
  • الشارة تتأخر حتى 60 ثانية عند إسناد مهمة جديدة؛ تُبطَل فورًا بعد إجراءات المدرب.
  • لم تُجرَّب الواجهات في المتصفح لأن الـ Migration لم تُطبَّق على قاعدة التطوير (dotnet ef database update). اختبار الحجز المتزامن على SQL Server ضمن S8.3.
