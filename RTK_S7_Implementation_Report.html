حدود المنهجية (للأمانة): k6 غير متاح فاستُخدم التطبيق الحقيقي داخل العملية (TestServer + مصادقة بالترويسات) مع SQL Server محلي حقيقي؛ المولّد والخادم يتشاركان المعالج ولا شبكة بينهما، فأزمنة العميل تحفّظية للخادم وتخلو من زمن الشبكة. أزمنة SQL مقيسة على الخادم عبر Interceptor للأوامر. لم تُقَس بيئة Azure SQL نفسها، فلا توصية بحجم Azure SQL مبنية على قياس؛ المؤشّر الوحيد: ~32 طلب/ث ≈ 3 أوامر لكل نبضة (~95 أمرًا/ث) بمتوسط أقل من 2ms على قاعدة محلية، ويُنصح بتكرار الاختبار نفسه (RTK_LOAD=1) على بيئة staging بحجم Azure المستهدف قبل يوم ذروة فعلي.

قائمة الأمان 11.1 — الدليل لكل بند

البندالحالةالدليل
IDOR✓Idor_StudentB… وIdor_AttemptOfAnotherStudent…: كل Action طالب ← 404 ولا أثر كتابة؛ 403 لأدمن بلا صلاحية (GET+POST)؛ نطاق الدفعات على SQL حقيقي. لم تُختبر عبر HTTP حالة «موظف بصلاحية وبلا دفعة» (مغطّاة على مستوى الخدمة في S6 وعلى SQL الحقيقي هنا).
Antiforgery✓الحارس (كل POST) + Posts_WithoutAntiforgeryToken… ← 400 فعليًا؛ لا IgnoreAntiforgeryToken.
Overposting✓حارس «لا Entity مربوطة»؛ كل الأكشنات تربط ViewModel/Input مخصّصًا.
XSS✓لا Html.Raw في Views الخطة (حارس)؛ اختبار ملاحظة <script> تُعرض مُرمَّزة؛ روابط الـ embed تُبنى من ExternalId المُتحقَّق. (ملاحظة: الجزئية المشتركة _ExamQuestionContent القديمة تستعمل Html.Raw(ToSafe(...)) لمحتوى الأسئلة — خارج نطاق RTK ولم تُمَس.)
تسريب الإجابات✓HTML (المحور/الحل/النتيجة) وJSON (SaveAnswer) بلا Explanation/VideoUrl/correctAnswer/الرقم المرجعي؛ E2E يؤكد في الصفحة الحقيقية.
Rate limiting✓429 فعلي: rtk-code عند الطلب 11، rtk-ping عند الطلب 21؛ الحمل (4 نبضات/د للطالب) لا يقترب من حد 20/د؛ rtk-exam مؤكَّد بالحارس.
Enumeration✓رقم خاطئ ← 200 برسالة عامة ثابتة ولا يتسرب الرقم الصحيح؛ غير المالك ← 404 موحّد.
التزامن✓RowVersion مُثبت على SQL حقيقي؛ 12 نبضة متزامنة وبدء/تسليم متزامن ← حالة واحدة وحدث واحد.
الخصوصية✓تقرير ولي الأمر/الدفعة بلا رقم مرجعي ولا طالب آخر (HTML فعلي)؛ حارس السجلات.
CSP/iframeيدويلا CSP/X-Frame-Options في كود التطبيق؛ فحص Nginx/Azure مُدرج في DEPLOY.md (لا يمكن فحص الخادم الحيّ من هنا).
